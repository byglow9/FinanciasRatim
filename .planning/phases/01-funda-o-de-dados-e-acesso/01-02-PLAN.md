## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → node_modules | Pacotes recentes entram no servidor que guarda a chave de conta de serviço |
| internet (Adoptium) → ~/.local/jdk | Tarball binário do JRE executado localmente |
| working tree → imagem Docker / repositório público | .env* e chaves poderiam vazar para a imagem ou para o git |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | npm install de firebase, firebase-admin, pluggy-sdk | high | mitigate | Instalar só o aprovado no Plano 01 (precondition da Task 2), com lockfile e `npm ci` no Docker; nenhum pacote novo além dos aprovados |
| T-01-02 | Information Disclosure | Dockerfile / contexto de build | high | mitigate | `.dockerignore` exclui `.env*`, `.planning`, `backups` e node_modules; `COPY` só de server e shared; `USER node` |
| T-01-03 | Tampering | Tarball do JRE Temurin | medium | mitigate | Baixar em diretório novo, conferir SHA-256 da API de assets antes de extrair, não executar nada do diretório de download |
| T-01-04 | Information Disclosure | Chave de conta de serviço e backups futuros | high | mitigate | `.gitignore` com `*-firebase-adminsdk-*.json`, `serviceAccount*.json` e `backups/` antes de qualquer script de admin existir |
