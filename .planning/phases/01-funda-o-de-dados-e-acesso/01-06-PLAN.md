## História de usuário (MVP)

**Como** casal (Ele e Ela), **quero** entrar cada um com e-mail e senha do Firebase e ter só nós dois lendo e gravando os dados do casal, sem perder histórico, **para que** as finanças fiquem privadas e as próximas fases partam de uma base segura (núcleo de cálculo, categorias estáveis, servidor atualizado).

<objective>
Ferramentas de migração de dados do cutover: backup/restauração por JSON, backfill de `ownerId` e `categoryId` com dry-run e idempotência, `verify` com contagens e o ensaio completo no emulador.

Purpose: FUND-02 exige `ownerId` em todos os dados sem perder nada; FUND-05 exige que o histórico aponte para o id estável da categoria. D-13 manda ensaiar com emulador e cópia exportada antes de tocar produção.
Output: quatro scripts importáveis (com CLI) e seus testes de emulador.

Regras de execução: stage apenas os arquivos listados em `files_modified`; nunca `git add -A`. Ambiente: `. ./scripts/dev-env.sh && COMANDO`. Testes de emulador rodam por `npm run test:emu` (concorrência 1). Scripts ficam em `server/scripts/` para resolver `server/node_modules`.
</objective>
